# Build pipeline, troubleshooting, and extending

## File roles

| File | Role |
|------|------|
| `karabiner.base.edn` | **Hand-written source.** Profile, templates, `:tos` notifications, layer triggers, and all rules *outside* the `;; BEGIN … ;; END` markers. Contains a `;; {{LAYERS}}` placeholder. |
| `layers.edn` | Hand-written shortcut-layer scaffolding, spliced into the `{{LAYERS}}` placeholder. |
| `config/*.yaml` | YAML definitions for app / workspace / shortcut / hyper layers (edit these). |
| `karabiner.edn` | **Generated** = base+layers merged, then YAML-driven blocks rewritten between markers. Don't edit. |
| `~/.config/karabiner/karabiner.json` | **Generated by goku** from the deployed `karabiner.edn`. Don't edit. |
| `data/fkey-pool.json` | Persistent F-key slot assignments for l1/l2/l3 (never reshuffled). |
| `data/devices_*.json` | Per-device UI settings (simple_modifications etc.), merged back in on deploy. |
| `lib/*.py`, `scripts/generate.py` | The Python generator (parser, F-key pool, EDN block generation). |
| `src/add-keymap/` | Go source for the `add-keymap` CLI; compiled binary committed at `scripts/executable_add-keymap`. |

## `build.sh` does two things

1. `sed` merges `layers.edn` into `karabiner.base.edn` at the `;; {{LAYERS}}` marker → writes `karabiner.edn`.
2. `uv run scripts/generate.py` rewrites the `;; BEGIN <NAME> … ;; END <NAME>` blocks in `karabiner.edn` from the YAML configs + `fkey-pool.json` (help text, app rules, shortcut layers, workspace rules, hyper rules).

`uv` handles PyYAML automatically — no venv/pip. Anything you type **between** `BEGIN/END` markers, or anywhere in `karabiner.edn`, is discarded on the next build. Hand-written rules must go in `karabiner.base.edn` outside the markers.

## Deploy / compile

`chezmoi apply` copies the source into `~/.config/karabiner/` and the `run_onchange_after_goku.sh` hook fires **when the deployed `karabiner.edn` hash changes** — it runs `goku` (with `GOKU_EDN_CONFIG_FILE=$HOME/.config/karabiner/karabiner.edn`) and merges saved device settings back into the profile. So the normal chain is just:

```bash
./build.sh && chezmoi apply
```

goku reads the **deployed** edn, never the chezmoi source — that's why you must `chezmoi apply` before any manual `goku`. The profile name `:Zaid` in the EDN must match the `"name"` field in `karabiner.json` (EDN keywords can't contain spaces).

## Troubleshooting

| Symptom | Cause / fix |
|---------|-------------|
| Change didn't take effect | You edited the chezmoi source but didn't deploy → `./build.sh && chezmoi apply`. Or you edited a generated file → move it to YAML/`base.edn`. |
| goku error / nothing recompiled | Check EDN syntax in `base.edn`/`layers.edn`; run `GOKU_EDN_CONFIG_FILE=$HOME/.config/karabiner/karabiner.edn goku` directly to see the error. |
| YAML ↔ EDN out-of-sync warning from `build.sh` | A hand-edited app rule diverged from `app.yaml`; reconcile in the YAML and rebuild. |
| Edited Go CLI, behavior unchanged | Rebuild the binary: `./src/add-keymap/build.sh` (needs Go at build time only), then `chezmoi apply`. |
| simple_modifications / fn keys / mouse reset | Those are UI-managed, not goku; re-snapshot with `scripts/save-devices.sh`. |

## Adding a whole new layer (e.g. `l4`)

1. Add an `l4:` section to `config/shortcuts.yaml`.
2. Add `'l4': ('!<mod>', 'shortcut-l4', '<description>')` to the `LAYERS` dict in `lib/generator.py`.
3. Add the trigger rule to `karabiner.base.edn` (a modifier + `right_option` that sets the `shortcut-l4` variable).
4. Add the `/` help rule for the layer to `karabiner.base.edn`.
5. `./build.sh && chezmoi apply`.
